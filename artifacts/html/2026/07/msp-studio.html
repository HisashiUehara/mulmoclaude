1 What is Microsoft Project?

          
Microsoft Project (MSP) is scheduling software for planning and tracking projects. You break the work into tasks, tell Project how long each one takes and which tasks depend on others, and it calculates the whole timeline for you — drawing a Gantt chart and finding the critical path.

          
Think of MSP as a super-smart spreadsheet that understands time. Change one task's length and every downstream date updates automatically.

          
The three questions every schedule answers: What needs doing (tasks), how long each takes (duration), and in what order (dependencies). Get those right and Project handles the maths.

          
🎯 In this app: the Build tab is a mini Project. Everything you learn here maps directly to a real MSP screen.

        


        

          
2 Tasks & Durations

          
A task is a single piece of work — e.g. "Demolition & strip-out". Its duration is the working time it needs, usually in days. Project counts working days only: a 5-day task starting Monday finishes Friday, not counting the weekend.

          
Duration = how long the work takes (elapsed working time). Work = total person-hours of effort. A 2-day task with 2 people can be 2 days duration but 32 hours of work.

          
⚠️ Duration is not a date. You give Project the duration; Project calculates the start and finish dates from the calendar and the task's dependencies. Never hand-type dates unless you must.

        


        

          
3 The WBS & Summary tasks

          
The WBS (Work Breakdown Structure) is your task list organised into a hierarchy. You group detailed tasks under headings called summary tasks. A summary doesn't have its own duration — it rolls up the span of its children.

          

1  Fit-out Project            (summary)
2   ├ Design                  (summary)
3   │   ├ Space planning      ████
4   │   └ Detailed design         ███████
5   └ Construction            (summary)
6       ├ Partitions                   █████
7       └ M&E first fix                 █████
          

          
In the Build tab, the Level column is your outline: increase a task's level to make it a sub-task of the one above. Any task that has sub-tasks under it is drawn as a bold summary bar.

          
💡 Good WBS rule: each task should be small enough to estimate confidently (often 1–15 days) but big enough to be worth tracking.

        


        

          
4 Dependencies (task links)

          
A dependency (or link) says one task can't start until another is done. The most common is Finish-to-Start (FS): Task B starts when Task A finishes. In the Build tab you set this with the Pred. (predecessor) column — list the IDs of tasks that must come first.

          

            
TypeCodeMeaningExample

            
Finish-to-StartFSB starts after A finishesPaint after plastering

            
Start-to-StartSSB starts when A startsCabling as partitions begin

            
Finish-to-FinishFFB finishes when A finishesTesting ends with build

            
Start-to-FinishSFB finishes when A starts(rare)

          

          
This app uses Finish-to-Start links (the 95% case). Real MSP supports all four plus lag (a wait, e.g. "FS+2d" = start 2 days after) and lead (an overlap, "FS-1d").

        


        

          
5 Milestones

          
A milestone is a zero-duration marker for a key moment — a sign-off, a delivery, "Occupation / Move-in". It has no length, so Project draws it as a diamond ◆ instead of a bar.

          
Set a task's Days = 0 in the Build tab and it becomes a milestone automatically. Milestones are great for reporting progress to stakeholders.

        


        

          
6 Reading a Gantt chart

          
A Gantt chart is the bar chart on the right of Project. The list of tasks runs down the left; time runs across the top. Each task's bar starts at its start date and its length equals its duration. Lines between bars show dependencies.

          
    
            
  • Bar position → when the task happens.
    • 
            
  • Bar length → how long it takes.
    • 
            
  • Bold black bars → summary tasks spanning their children.
    • 
            
  • Diamonds → milestones.
    • 
            
  • Shaded columns → non-working days (weekends).
    • 
          

          
👀 Open the Build tab and watch the Gantt redraw every time you change a duration or predecessor — that live feedback is exactly how MSP feels.

        


        

          
7 The Critical Path

          
The critical path is the longest chain of dependent tasks — it sets the shortest possible project duration. Tasks on it have zero slack (float): delay one and the whole finish date slips. Project highlights them in red.

          
Slack / Float = how long a task can slip without delaying the project. Critical tasks have 0 slack. Non-critical tasks have some buffer.

          
Why it matters: if you need to finish sooner, you must shorten critical tasks — speeding up a non-critical task changes nothing. This is the single most powerful idea in scheduling.

          
In the Build tab, red bars = critical. Try increasing a red task's duration and watch the project finish date move. Increase a blue (non-critical) task a little and it won't.

        


        

          
8 Resources & Calendars

          
Resources are the people, teams or equipment doing the work (e.g. "Main Contractor", "M&E Sub"). Assigning them lets Project spot over-allocation — someone booked on two tasks at once. The Resource column in the Build tab feeds straight into the exported file.

          
A calendar defines working time. The default Standard calendar is Mon–Fri, 8 hours/day. That's why weekends are skipped when Project schedules your tasks. You can add holidays or night shifts by editing the calendar.

        


        

          
9 Baselines & tracking

          
Once your plan is approved you set a baseline — a saved snapshot of the planned dates. As work happens you enter % complete. Project then compares actual vs baseline so you can see slippage early.

          
🧭 Planning is half the job; tracking is the other half. A schedule you never update is just a guess. Update weekly.

📖 Glossary

          

            
Task
A single unit of work in the schedule.

            
Duration
The working time a task needs (e.g. 5 days). Weekends excluded.

            
Work
Total effort in person-hours, separate from duration.

            
WBS (Work Breakdown Structure)
The hierarchical outline of all tasks.

            
Summary task
A heading that rolls up the span of the tasks beneath it.

            
Predecessor / Successor
The task that comes before / after in a dependency.

            
Dependency (link)
A rule connecting two tasks, e.g. Finish-to-Start.

            
Lag / Lead
A delay (+) or overlap (−) added to a dependency.

            
Milestone
A zero-duration marker for a key event, drawn as a diamond ◆.

            
Gantt chart
The timeline bar chart of the schedule.

            
Critical path
The longest dependent chain; it sets the project's finish date.

            
Slack / Float
How long a task can slip without delaying the project.

            
Resource
A person, team or equipment assigned to a task.

            
Calendar
Definition of working days/hours used for scheduling.

            
Baseline
A saved snapshot of the approved plan for comparison.

            
MSPDI
Microsoft Project Data Interchange — the XML format this app exports.
