# WeeklyReport — 確認UI仕様（ステップ5 / Stage 4 で実装）

ステップ5「人間が日英を横並びで確認・承認」の画面仕様。**この段階が停止点**であり、
承認をスキップする自動モードは作らない。実装は Stage 4（コレクションのカスタムビュー
`views/confirm.html`, capabilities `["read","write"]`）で行う。本ファイルはその仕様。

## 目的
- 承認者（人間）が、DSL の各項目の **原文（日本語）と訳文（英語）を横並び**で確認する。
- `confidence: low` の項目を**強調**し、確認漏れを防ぐ。
- 問題なければ**承認**して `status` を `承認済` に進める（＝S6 流し込みの解錠）。

## レイアウト（日英横並び）
- 1項目 = 1行。列: `項目ID` | `参照元(source_location)` | `原文` | `訳文` | `確信度` | `操作`。
- `原文` と `訳文` を左右に並べ、対応が一目で分かるようにする。
- 訳文セルは**その場編集可**（人間が微修正できる）。編集したら該当項目に「人手修正」印を付ける。

## low の強調
- `confidence === "low"` の行は背景を警告色（アンバー系）にし、`LOW` バッジを表示。
- 画面上部に「low: N件 / 全 M件」のサマリと、**「lowのみ表示」フィルタ**を置く。
- low項目は既定で最上部にソート表示（確認を促す）。

## 承認フロー
- **「承認」ボタン**押下で:
  - `status` を `承認済` に更新
  - `approvedBy`（承認者名）・`approvedAt`（承認日）を記録
  - `auditLog` に `{ when, who, stage:"S5 承認", detail }` を追記
- ガード:
  - 未確認の low 項目が残る場合は確認ダイアログを挟む（「low N件を未チェックです。承認しますか？」）。
  - `訳文` が空の項目が1つでもあれば承認不可（S3 未完扱い）。
- **差し戻し**: 「再翻訳へ戻す」ボタンで `status` を `翻訳済`→（実質 S3 やり直し）に戻せる。承認と再翻訳以外の状態遷移はUIから行わない。

## やらないこと（制約）
- ❌ 自動承認・一括承認で人間の確認を省くモード。
- ❌ UI から `完成` へ直接遷移（`完成` は S6 engine の流し込み成功時のみ）。
- ❌ `confidence` を UI 側で勝手に high に書き換える（人間の判断は訳文修正で表現し、confidenceはAIの申告として残す）。

## E2E（Stage 4 の合格条件）
- `../fixtures/gold/expected.dsl.json` を読み込み、low項目 `006/007/008/010` が強調表示される。
- 承認操作で `status: 承認済`・`approvedBy`・`approvedAt`・`auditLog` が正しく書かれる。
- 訳文空／low未確認のガードが機能する。
